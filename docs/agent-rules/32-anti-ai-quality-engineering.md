# 32 — Anti-AI Slop Quality Engineering & Production Standards

Zero-tolerance rules against generic AI placeholders, artificial patterns, and hallucinated logic.

---

## 1. What is "AI Slop"?
AI slop refers to superficial, generic code generated by careless LLMs:
- Fake dummy data (`"John Doe"`, `"123 Fake Street"`) hardcoded into production components.
- Incomplete placeholder functions (`// TODO: implement later` or `throw new Error("Not implemented")`).
- Excessive, repetitive helper functions that wrap standard browser primitives for no reason.
- Hallucinated PostEx API endpoints or fabricated payload parameters.
- Blanket `try/catch` blocks that silently swallow critical bugs.

---

## 2. The Anti-Slop Production Standard
1. **Real Production Logic**: Every function must be fully implemented, tested, and resilient to failure.
2. **Defensive Validation**: Validate real Pakistani telephone numbers (`03XXXXXXXXX`), legitimate PostEx tracking formats (`CN-XXXX`), and actual operational cities before sending requests.
3. **Transparent Error Handling**: Show actionable, human-readable error messages to the merchant so they can resolve the issue immediately.
4. **Architectural Permanence**: Write clean, maintainable, TypeScript-strict code that human engineers and senior developers will admire and enjoy working with.

---

## 3. RULE ANTI-AI-NO-DEV-TRIVIA — Strict Ban on Unwanted Developer Brag Notes & AI-Style Clutter in SaaS UI

1. **Zero Technical Developer Brag Notes**:
   - Strictly forbidden to display internal backend implementation details to merchants in the UI (e.g. *"Profile avatar is automatically compressed to 10–20 KB WebP and permanently stored on Supabase Storage"*, *"Stored via PostgreSQL Row Level Security"*, *"Converted via canvas 82%"*, *"Saved to cloud storage bucket"*).
   - Enterprise merchants expect a polished, disciplined Apple/Stripe-grade logistics SaaS. Backend infrastructure, bucket names, image codecs, and compression algorithms must remain completely silent and invisible.
2. **Zero Confusing / Artificial Status Badges & Mode Labels**:
   - Strictly forbidden to render artificial status labels like *"Manual Save Mode"*, *"Auto-Save Active"*, *"Sync Mode: Idle"*, or unnecessary developer commentary tips (e.g., *"Tip: Google Gemini gives 1,500 free requests per day"*).
   - Use clean, standard UI elements only: authoritative action controls (`Save Settings`, `Discard`), inline field validation errors when input is invalid, and essential logistics connectivity state (`PostEx Connected`, `Verified`).
3. **Professional SaaS Copywriting Standard**:
   - Every single visual element, label, and toast string must serve a direct business purpose for booking, dispatching, tracking, or user administration.
   - User feedback must always communicate the business outcome, never the technical plumbing:
     - ❌ Banned: *"Profile avatar saved to cloud storage! (15.2 KB WebP)"*
     - ✅ Allowed: *"Profile photo updated."*
     - ❌ Banned: *"Converting to WebP..."*
     - ✅ Allowed: *"Uploading..."*
     - ❌ Banned: *"All preferences saved successfully to cloud storage."*
     - ✅ Allowed: *"All preferences saved successfully."*
4. **Zero AI-Looking Filler Elements**:
   - If an element does not help the merchant create a consignment note, track a courier parcel, configure shipping credentials, or manage their account, it must NOT exist in the interface. AI-like educational disclaimers and conversational padding are permanently banned.
